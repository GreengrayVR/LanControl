# Приймальні випробування на Windows

Виконувати на двох тестових Windows 10/11 x64 ПК або VM: сервер `6kabinet` та клієнт з ім’ям із computers.txt. Потрібен ще один стандартний користувач для перевірки сеансів. Фіксуйте фактичний результат, версію Windows, Qt та номер клієнта. Цей список не є звітом про вже виконані перевірки.

| Дія | Очікуваний результат |
| --- | --- |
| Запустити Build.ps1 | Обидва EXE зібрані, ctest успішний, Qt/OpenSSL DLL і TLS-плагін у пакетах |
| Запустити Build-SingleFileClient.ps1 | Один LanClient.exe з вбудованими налаштуваннями, Qt та MSVC Runtime; import table містить лише системні Windows DLL |
| Запустити статичний LanClient.exe --self-test у порожній папці | Exit code 0 без JSON/DLL поруч і без розпакування файлів |
| Установити статичний клієнт із робочого столу з іншими файлами | Служба й агент працюють через Schannel; установлено тільки клієнтські EXE, без DLL і без копіювання сусідніх файлів |
| Підготувати deployment, перевірити client/client.json | Єдина папка client для всіх ПК; спільний токен відповідає sharedClientToken сервера, pin правильний, server.key відсутній |
| Установити той самий пакет на всі шість ПК без редагування JSON | Кожен ПК визначає власне ім’я; сервер одночасно показує KABINET6-R1–KABINET6-R6 |
| Перейти зі старих персональних пакетів на спільний | Чинний сертифікат, приватний ключ та старі токени збережено; раніше встановлені клієнти підключаються |
| Установити клієнт стандартним користувачем з UAC адміністратора | Автослужба LocalSystem, HKLM Run, захищені каталоги, немає кнопки клієнта на панелі завдань |
| Перезавантажити клієнт без входу | Служба Running, сервер показує ПК зеленим |
| Увійти першим і другим користувачем | У кожному активному сеансі один агент; браузер відкривається з правами відповідного користувача |
| Надіслати https URL усім і вибраним | Відкривається лише на адресованих ПК; у журналі accepted by service |
| Надіслати 3 URL поспіль за секунду | Агент обробляє всі три команди, кожну один раз |
| Надіслати file://, javascript:, URL з логіном або переносом рядка | GUI відхиляє введення |
| Від’єднати мережевий кабель | Статус червоний до 66 с, клієнт продовжує повторні спроби |
| Закрити сервер через трей й запустити знову | Автоматичне підключення до 20 с після доступності сервера |
| Натиснути X на сервері | Вікно сховане, значок трею є, команди продовжують працювати |
| Спробувати неправильний токен / інший TLS-сертифікат | Підключення відхилене, команди й оновлення не виконуються |
| Спробувати спільний токен із невідомим ім’ям ПК | Підключення відхилене; список дозволених імен не змінюється |
| Змінити server.crt на прострочений або з іншим DNS-ім’ям | TLS відхилений навіть із відповідним pin |
| Зібрати Version 2, Publish-Update -Version 2 | Клієнт завантажує файл, служба та агенти переходять на versions/2, сервер показує версію 2 |
| Обрізати EXE або змінити sha256 маніфесту | Оновлення не встановлюється; чинна служба залишається працездатною |
| Відключити мережу посеред оновлення | Чинна версія працює, після відновлення завантаження починається заново |
| Спробувати опублікувати Version 1 після Version 2 | Сценарій/клієнт відхиляє пониження |
| На тестовому deployment опублікувати невалідний EXE з коректним hash і вищим номером | Після невдалого старту повертається попередня служба; failed-update.json містить номер; повторного встановлення немає |
| Опублікувати EXE з вбудованою Version 2, але маніфестом Version 3 | Перевірка під час старту служби відхиляє невідповідність; відкат |
| Звичайним користувачем змінити installed EXE, client.json, staging, чергу | Доступ на запис заборонено ACL |
| Виконати --uninstall | Службу й HKLM Run видалено, агенти завершилися, файли можна прибрати вручну |

Під час оновлення спостерігайте client.log та Get-Service. Підтвердження доставки в GUI стосується служби: успіх HTTP-відповіді вебсайту браузера тут не перевіряється.
